# Implementation decisions

This record preserves the sixteen rulings supplied for Phase 1, including rationale and cost if wrong.

1. **T6 error paths:** T6 wraps `TheoryError`/`ValueError` from theory/rhythm/drums into `SpecError` with a field path. **Rationale:** spec §4 requires a path in messages. **Cost if wrong:** small error-plumbing refactor.
2. **T9 install tests:** Use a fake repository fixture in a temporary directory, not the real repository. **Rationale:** installation must be testable before skills exist. **Cost if wrong:** none functionally.
3. **Reviewer models:** Reviewers use Sonnet except T4/T6/T7, which use Opus. **Rationale:** the user asked to minimise cost. **Cost if wrong:** a subtle bug reaches the final Opus review.
4. **Drum map:** The `drum_synth` map is CUSTOM; voices without a distinct sound are `unsupported`. Task 5 `resolve_drum_map("soundcraft")` omits them; Task 6 raises `SpecError`: `voice 'X' is not available in drum_synth (use drum_map gm with a GM plugin, or another voice)`. **Rationale:** spec §6 forbids silent wrong output. **Cost if wrong:** users must pick another voice instead of hearing a substitute.
5. **Secondary X/Y chords:** Use 11 semitones for degree VII regardless of target mode; the key's own numerals stay natural minor. **Rationale:** harmonic convention for leading-tone chords. **Cost if wrong:** one degree tweak.
6. **Lowercase extensions:** Lowercase `add9`/`add11` numerals raise `TheoryError`; do not add new `QUALITIES`. **Rationale:** spec §4 fixes the quality list. **Cost if wrong:** users write `iadd9` and get an error instead of a chord.
7. **Task 5 model:** Task 5 was implemented on Sonnet instead of the plan's Opus. **Rationale:** the brief pins every value/formula, so the work is transcription plus tests; the user wants lower cost. **Cost if wrong:** an extra fix round.
8. **Checkout:** Continue the user-approved feat/phase1 checkout in place after provider handoff; do not create a new worktree or restart completed tasks. **Rationale:** preserve the current authorized state. **Cost if wrong:** changes remain on the existing feature branch.
9. **Model mapping:** Map prior Opus core roles to gpt-6.1-sol high, prose/CLI roles to gpt-6.1-sol medium, mechanical roles to gpt-6-luna medium; final review to gpt-6-astra high. The user authorized cheaper cross-provider delegates and the Claude session was exhausted. **Cost if wrong:** an extra fix round. Commit attribution must name the actual contributing model, not assert a Claude contribution that did not occur.
10. **Antigravity manifest:** Task 9 root Antigravity `plugin.json` uses only name/description because the current official schema forbids version/author/license. Compare versions only across Claude/Codex manifests; copyright/license remain in LICENSE and docs. Actual schema checks override the provisional three-manifest version test. Retain the Codex compatibility overlay; coexistence is unverified until a real host test. **Cost if wrong:** Antigravity displays no manifest version and needs native validation later.
11. **Platform path separator:** Task 8 `default_dirs` splits `CLAP_PATH` using the requested target platform separator (semicolon for Windows, colon otherwise), which equals `os.pathsep` on the running native platform. **Rationale:** resolves the plan's Linux-path test on a Windows development host. **Cost if wrong:** only simulated foreign-platform calls differ.
12. **Plugin categorization:** Compare accent-folded, casefolded names while preserving original display/path strings. **Rationale:** makes the explicit Serum-with-accent fixture match synth without adding category keywords. **Cost if wrong:** a few accented names match more broadly.
13. **Remaining work:** Use concise briefs and one active implementer; Luna medium for bounded docs/mechanical tasks, Sonnet medium when cross-provider fallback is needed or prose requires broader judgment; one scoped standard-tier review/application per task, with no duplicate test runs without changed code or a concrete concern. **Rationale:** latest user explicitly prioritizes economy. **Cost if wrong:** a scoped correction or capability escalation only when demonstrated necessary.
14. **Final integration review:** Use gpt-6.1-sol high rather than automatically selecting a higher-price model. **Rationale:** prior task reviews and live engine evidence narrow remaining risk, and the latest user explicitly prioritizes economical model selection. **Cost if wrong:** a cross-task defect may require a later scoped correction.
15. **Combined final review:** Combine Task 18 documentation review with the final whole-branch integration review in one reviewer dispatch, checking both requirement sets. **Rationale:** avoids a duplicate final-context review seat. **Cost if wrong:** documentation and integration receive one independent pass rather than two overlapping passes.
16. **Requested phrase duration:** Preserve requested trailing-rest duration with an optional intended track-end tick carried from renderer to SMF EOT, at least final note-off; retain existing direct callers/defaults and do not lengthen sounding notes. **Rationale:** this restores requested phrase duration without adding composition features. **Cost if wrong:** a host may ignore EOT; document/test host behavior separately rather than invent fake notes.
